# AI 科研文献速递系统：核心设计基线

版本：`1.1.0-draft`  
状态：可进入 MVP 实现  
数据库基线：SQLite（MVP），兼容迁移至 PostgreSQL  

本目录冻结第一版开发前必须明确的三项设计：

1. [数据库 ER 设计](01-database-er-design.md)
2. [Agent 状态流转设计](02-agent-state-flow.md)
3. [Prompt 工程规范](03-prompt-engineering-spec.md)

可执行的首版 Prompt 配置位于 [`config/prompts.v1.yaml`](../../config/prompts.v1.yaml)。

## 统一设计目标

- 每一条科研结论都能追溯到论文、原文证据和处理版本。
- 确定性工作由普通程序完成，LLM 只负责语义判断、结构化分析与写作。
- 每个处理步骤可重试、可跳过、可人工复核，且不会重复写入数据。
- MVP 只覆盖 PubMed 文献发现、验证、分析、分类、报告生成与静态发布。
- MVP 正式发布前强制执行批次级人工确认；Quality Gate 只负责质量评分和预览资格。
- 微信公众号采集、PI 追踪、用户系统、知识图谱和科研问答不进入首版。

## 统一术语

| 术语 | 定义 |
|---|---|
| `pipeline_run` | 一次定时或手动触发的完整处理批次 |
| `paper` | 去重后的论文主记录 |
| `paper_task` | 某篇论文在某批次中的处理状态与重试信息 |
| `source_record` | 从外部数据源取得、尚未标准化的原始记录 |
| `verification` | 对 PMID、DOI、URL 和元数据一致性的确定性校验 |
| `analysis` | LLM 基于可用摘要或全文生成的结构化科研分析 |
| `evidence` | 支撑 AI 结论的可定位原文片段 |
| `report_item` | 面向最终科研日报展示的一篇文献内容 |
| `prompt_version` | 一份不可变 Prompt 模板版本及其输出契约 |

## 关键技术决策

| 编号 | 决策 | 原因 |
|---|---|---|
| ADR-001 | MVP 使用 SQLite，生产演进目标为 PostgreSQL | 降低首版部署复杂度，同时保留并发和检索升级路径 |
| ADR-002 | 论文主数据与批次处理状态分离 | 同一论文可能出现在多个检索批次中，不能重复存储或互相覆盖状态 |
| ADR-003 | 原始响应只存必要快照和哈希 | 保证审计能力，避免无边界保存全文及版权风险 |
| ADR-004 | DOI/PMID/URL 验证不交给 LLM | 这些是确定性任务，应由 API 和程序规则完成 |
| ADR-005 | LLM 输出必须通过 JSON Schema 校验 | 防止自由文本破坏后续分类、页面生成和审计 |
| ADR-006 | 报告发布前设置质量门禁 | 证据不足、字段冲突或高风险表述不得自动发布 |
| ADR-007 | MVP 正式发布采用批次级人工确认 | 先生成可检查预览，系统稳定后再评估无人值守发布 |
| ADR-008 | 增加轻量 `content_snapshots` | 冻结 AI 实际输入，同时避免演变为受限全文存储系统 |
| ADR-009 | MVP 先用 5–10 篇小型测试集 | 先验证端到端流程；50 篇 Golden Dataset 保留为正式评测目标 |

## 实现前完成标准

- ER 表字段、关系、唯一约束和删除策略已经确定。
- 状态机中的每个状态都有唯一责任方、进入条件和退出条件。
- 每个 LLM 节点都有版本化 Prompt、输入契约、输出 Schema 和评测指标。
- 三份设计中的名称保持一致；代码不得另造同义状态或字段。
